# Комплексные мультиблоки

Реализована общая система правил оболочки, а не копия конкретной печи другого мода. Обычные фиксированные схемы `MultiblockDefinition` остаются отдельной системой.

## Что можно менять

Один тип установки поддерживает несколько размеров, сменные функциональные блоки и перенос взаимодействующих узлов. Контроллер всегда расположен на передней стене, на один блок выше пола; всю конструкцию можно повернуть в четыре стороны. Правила задают открытый верх или закрытую крышу, допустимые материалы пола/стен, зоны функциональных блоков и минимальное/максимальное число каждой роли.

Сборка производится настройщиком. Размеры распознаются по миру; автоматически конструкция не собирается. Контроллер сохраняет размеры и содержимое. Замена подходящей части изменяет характеристики после проверки; неподходящая часть останавливает установку. При изменении размеров сначала разберите конструкцию настройщиком или снимите часть оболочки, затем соберите заново. Shift+настройщик разбирает и поворачивает контроллер.

Функциональные части и оболочка принадлежат одному контроллеру. Владение сохраняется в SavedData измерения и не исчезает при выгрузке чанков или перезапуске. Незагруженная конструкция приостанавливается без принудительной загрузки. Удаление контроллера освобождает владение. Удаление частей сохраняет предметы и металл в контроллере; разрушение самого очага возвращает металл предметами с тем же количеством материала.

ПКМ по части собранной конструкции передаёт действие её контроллеру: загрузка сырья/топлива или информация над хотбаром; жидкостные контейнеры обслуживаются только жидкостными портами и топливными баками. Shift+ПКМ контроллера открывает подробный интерфейс. Настройщик также работает через части. Воронки подают сырьё через предметные порты или сверху контроллера, твёрдое топливо сбоку; литейные сливы также являются портами Fabric Fluid Storage.

Модульный комплекс сохраняет обычные модели всех своих блоков. Контроллер дополнительно рисует только расплавы, потоки и предметы в реальных внутренних границах. Фиксированный нормализованный рендер обычных мультиблоков сохранён. JEI показывает малые примеры, 3D-предпросмотр и допустимый диапазон размеров.

## Регистрация

Источник — `complex_multiblocks` в `src/main/content/smog.content.json`. Пример:

```json
{
  "id": "smog:copper_hearth",
  "controller": "smog:copper_hearth",
  "closed": false,
  "min_width": 3, "max_width": 11,
  "min_depth": 3, "max_depth": 11,
  "min_height": 3, "max_height": 11,
  "floor": "#smog:hearth_floor",
  "casing": "#smog:copper_masonry",
  "roles": [
    {"name":"fuel", "block":"#smog:smeltery_heaters", "zones":["floor","wall"], "min":1, "max":4},
    {"name":"spout", "block":"smog:casting_spout", "zones":["wall"], "min":0, "max":2147483647}
  ]
}
```

Этот пример сокращён: рабочая запись также содержит воздушные вводы и футеровку. Блок роли может быть конкретным ID или тегом. Для зон используются `floor`, `wall`, `roof`, `interior`; углы крыш относятся к стенам. Свободный интерьер должен содержать воздух, кроме явно разрешённых ролей. Поиск ограничен указанными размерами; общая защита API — не больше 11×11×11. Контроллер нельзя ставить в угол стены.

Реестр `ComplexMultiblocks` связывает правила с ID контроллера. `ComplexMultiblockDefinition.inspect` проверяет выбранный размер и возвращает счётчики ролей; `discover` находит размер. `MachineEntity.complexRoles()` передаёт эти счётчики логике установки. Ёмкость очага задаёт пустой внутренний объём; футеровка меняет потери тепла, а размер камеры печи — величину партии, без отдельного алгоритма сборки для каждой машины.

Установка регистрируется в `machines` как обычно. Запись `multiblocks` с тем же ID служит малым примером для JEI; в мире комплекс проверяется по правилам оболочки, а не по этому примеру. Для нестандартных форм, наклонных конструкций и перемещаемого контроллера понадобятся другие валидаторы: текущий общий тип описывает прямоугольные оболочки.

В 0.7.2 функциональные роли запрещены на пересечениях двух или трёх внешних границ: рёбра и углы отданы кладке. Декоративная роль `lining` разрешена там как материал оболочки. Для открытой чаши проверяется, что её стены не продолжаются выше выбранного обода. При отрисовке пустые внутренние ячейки не превращаются в меши: контроллер рисует отдельную поверхность жидкости внутри реальной полости.

Поворот настройщиком — только **Shift+ПКМ**, и для отдельных частей, и для контроллеров. Обычный ПКМ не меняет направление: на контроллере он только пытается собрать структуру, на отдельной детали поворот не выполняется.

## Порты и насадки (0.7.5)

Стеновые блоки теперь называются жидкостным и воздушным портами. Существующие ID сохранены для совместимости миров. Порт входит в оболочку, а насадка — отдельный внешний блок. К жидкостному порту крепится литейный краник, к воздушному — воздушная насадка. Установка на неподходящий блок отклоняется. Насадки изначально закрыты; ПКМ пустой рукой открывает/закрывает их и меняет положение рукояти.

Пример по высоте: порт в стене на Y, краник снаружи на том же Y, стол или первый желоб под краником на Y−1. В мире видна вертикальная струя. Голый порт и закрытый краник металл на стол не подают. Внешние жидкостные трубы по-прежнему могут подключаться непосредственно к порту. Меха работают рядом с открытой воздушной насадкой, соединённой с портом собранного очага.

Поворот только Shift+ПКМ настройщиком. Обычный ПКМ настройщиком не вращает ни одиночные детали, ни контроллер. Диапазоны в русских подсказках и JEI записываются словами: «от 3 до 11». Проверены 25 серверных GameTest, включая обе насадки и настоящий Shift-путь взаимодействия.
