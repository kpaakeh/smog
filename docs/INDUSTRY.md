# Smog 0.4 — механизмы, энергия и модели

Сначала рабочая основа; баланс, сложные модели и анимации добавляются позже.

## Где рисовать

- Текстуры: `src/main/resources/assets/smog/textures/block` и `textures/item` (PNG).
- Модели технических блоков и компонентов: `src/main/resources/assets/smog/models/block` (JSON).
- Например: `electric_furnace.json`, `crusher.json`, `press.json`, `connector_lv.json`, `solar_cell.json`.
- Общие модели собранных генераторов: `generator_solar.json`, `generator_wind.json` и остальные `generator_*.json`.
- Общая модель тестового мультиблока: `assembled_machine.json`.

Открой JSON в Blockbench как Minecraft Java Block/Item model, замени геометрию и экспортируй обратно с тем же именем. Текстуры используют ссылки `smog:block/<имя>`; PNG можно менять независимо. Технические блоки имеют собственные `elements`, включая каркасы, трубы, стойки и выступающие части. Рудные и складские блоки остаются обычными кубами. Формат JSON задаёт статическую геометрию; анимация роторов пока не реализована.

Обычные модели используют координаты 0…16 на блок; небольшие выступы допускаются. Модель собранного мультиблока **нормализована в 0…16 по всем осям**: рендер масштабирует её до полных размеров конструкции. Не экспортируй её сразу в размере нескольких блоков, иначе размер применится дважды. Исходные блоки скрываются визуально; коллизии остаются от составляющих блоков.

После изменения PNG/JSON в dev-клиенте перезагрузи ресурсы; для готового JAR пересобери проект. `tools/generate_textures.py` и `tools/generate_industry_assets.py` создают отсутствующие файлы и сохраняют существующие рисунки/модели. `generate_textures.py --force` перезаписывает PNG — не используй поверх своих правок. Python для обычной сборки не нужен.

## Механизмы

ПКМ открывает GUI. Настройщик поворачивает обычный механизм по ПКМ; рабочая сторона — направление `facing`. Кнопка I/O включает/отключает работу. Вход слева, выход справа. Предметы, энергия и прогресс сохраняются. Воронки кладут на вход, извлекают выход.

| Механизм | Предел обмена, FE/тик | Работа |
|---|---|---|
| Электропечь | 32 | Ванильные рецепты обычной плавки; 100 тиков, 4 FE/тик |
| Дробитель | 32 | Сырьё → дроблёная руда → осколки → пыль; 60 тиков, 8 FE/тик |
| Пресс | 128 | Слиток → пластина; 80 тиков, 16 FE/тик |
| Разрушитель | 32 | Передний блок → выход; 64 FE за успешное действие |
| Ставщик блоков | 32 | Входной BlockItem ставится перед механизмом; 32 FE за действие |
| Насос | 32 | Пустое ведро + источник впереди → полное ведро; 32 FE |
| Ставщик жидкостей | 32 | Полное ведро → жидкость впереди + пустое ведро; 32 FE |
| Твердотопливный генератор | 32 | Ванильное печное топливо; 16 FE/тик |

Мировые механизмы пытаются действовать раз в 20 тиков. Разрушитель не ломает неразрушимые блоки и ждёт свободного выхода. Работа выполняется в загруженных чанках. Насос и ставщик жидкостей пока используют вёдра, без резервуаров и труб. Разрушитель принимает добычу одного вида за действие; сложные смешанные дропы пока пропускаются. В дробителе также есть булыжник → гравий → песок. Железные и медные пластины доступны через пресс. JEI показывает категории дробления и прессования; рецептов осколков/дроблёной руды на верстаке нет. Самородки и осколки — отдельные предметы.

## Электричество

Smog показывает энергию в FE. В JAR встроена **Team Reborn Energy 5.0.0** — стандартный Energy API для Fabric. Все машины публикуют sided EnergyStorage, генераторы и коннекторы передают энергию соседним устройствам других Fabric-модов через тот же API. Числовые значения буферов сохранены: 1 единица Smog FE = 1 единица Energy API, без скрытого множителя.

Машины принимают энергию со всех сторон, генераторы отдают, коннекторы и трансформаторы принимают и отдают. Внешний источник сам проталкивает энергию в машину/коннектор; провода её не высасывают. Можно подключить внешний генератор к коннектору, провести провод к Smog-машине либо питать внешний потребитель от Smog-генератора через удалённый коннектор. Механизмы принимают FE независимо от материала провода. Материал определяет пропускную способность и длину соединения. Пределы ввода/вывода общие для всех сторон и учитывают несколько обращений за один тик.

Обмен выполняется транзакциями Fabric: отмена откатывает оба буфера и лимиты передачи. Неполный приём списывает только принятую энергию. Выключенные/неполные устройства не обмениваются энергией. Накопитель каждого коннектора вмещает восемь тиков его номинальной передачи.

Исходники API и правила интеграции: https://github.com/TechReborn/Energy . Совместимость относится к Fabric-модам, использующим этот API; Forge/NeoForge — другие загрузчики.

| Материал | Скорость передачи | Длина одного провода | Буфер коннектора |
|---|---:|---:|---:|
| Медь | 128 FE/тик | 24 блока | 1024 FE |
| Алюминий | 64 FE/тик | 48 блоков | 512 FE |
| Серебро | 512 FE/тик | 48 блоков | 4096 FE |
| Сталь | 32 FE/тик | 64 блока | 256 FE |
| Золото | 256 FE/тик | 32 блока | 2048 FE |
| Олово | 32 FE/тик | 16 блоков | 256 FE |

Это стартовый игровой баланс. Сталь даёт длинные прочные пролёты, серебро — высокую пропускную способность. Реальная химия и электрические потери пока не моделируются.

Поставь коннекторы рядом с источником и потребителем. Коннектор крепится на любую из шести сторон блока: пол, потолок или стены. Нажатая грань задаёт направление `attachment`; модель и точка подключения провода поворачиваются вместе. Катушкой соответствующего материала нажми ПКМ по первому и второму коннектору. Тратится одна катушка на соединение; путь проверяется на препятствия. Провод рисуется объёмной провисающей линией. Shift+ПКМ катушкой по коннектору снимает соединения с возвратом катушек. После завершения/отмены соединения катушка снова складывается с неиспользованными; старые координатные данные версии 0.3.0 автоматически очищаются в инвентаре. Уничтожение конца также удаляет провод. Связи сохраняются отдельно для каждого измерения; выгруженные чанки не загружаются принудительно.

Соседние устройства обмениваются FE с учётом лимита каждого устройства. Коннекторы передают энергию дальше; потребители используют её для своей работы. Распределитель энергии принимает FE и выдаёт их с выбранным пределом: кнопка + в GUI меняет 32/64/128/256/512 FE/тик. Числовая энергия сохраняется, лимит источника и пропускная способность проводов ограничивают передачу.

Медь и золото используют ванильные слитки. Алюминий, серебро и олово генерируются своими рудами и имеют все 11 форм семейства. Стальная смесь (железный слиток + уголь) плавится в стальной слиток; у стали также есть самородки, пыль, пластины и блок. Рецепты всех шести катушек используют соответствующий металл.

Для совместимости с миром внутренние ID старых предметов и файлы моделей сохранены: `*_lv` теперь медные, `*_mv` — золотые, `*_hv` — серебряные. В игре используются названия материалов. Старые SavedData проводов читаются и переводятся на материалы без удаления связей.

## Мультиблочные генераторы

Для всех используется **один `generator_controller`**. Собери схему из JEI вокруг него и нажми ПКМ настройщиком по контроллеру. При нажатии определяется тип структуры; без настройщика она не собирается. Это также относится к тестовому мультиблоку. Поломка составной детали останавливает генерацию и возвращает отдельные модели. После ремонта снова нажми настройщиком. Shift+ПКМ настройщиком разбирает конструкцию и поворачивает контроллер. При выгрузке необходимых чанков работа приостанавливается до их возвращения. Собранная конструкция отображается единой моделью её полного размера.

| Тип | Предел выдачи, FE/тик | Условия/выработка |
|---|---|---|
| Солнечный | 32 | Открытое небо, дневное время; 8 FE/тик, в дождь 3 |
| Молниевый | 512 | Молния в пределах 5 блоков по горизонтали и 12 по вертикали; 50 000 FE за уникальный разряд |
| Тепловой | 32 | Лава, магма, огонь или горящий блок рядом; до 32 FE/тик |
| Потоковый | 32 | Текущая вода рядом; до 32 FE/тик |
| Ветровой | 128 | Открытое небо, верх конструкции от Y=70; мощность растёт с высотой, дождь добавляет 8 FE/тик |
| Паровой | 128 | Вода и источник тепла рядом; 48 FE/тик |
| Геотермальный | 128 | Лава рядом; 64 FE/тик |

Для тепла/воды сканируется объём конструкции с рамкой в один блок. Тепло и жидкости пока не расходуются: это основа генерации от окружения. Молниевый генератор сам не создаёт и не притягивает молнию; можно использовать ванильный громоотвод рядом. Ёмкость генераторов 200 000 FE, потребителей 64 000 FE.

Имя мультиблока в JEI задаётся полями `display` / `display_ru` его записи каталога и показывается над размерами.

JEI-превью: **ЛКМ + движение — вращение, колесо — зум, ПКМ — собранный вид, СКМ — сброс**. В Minecraft 26.3 SDL-коды мыши отличаются от старых версий; используются актуальные константы InputConstants.

## Регистрация и расширение

`src/main/content/smog.content.json` задаёт контент. `model` выбирает собственную модель блока; `kind`, `transfer_rate`, `capacity`, `work_ticks`, `cost` задают поведение механизма. Смотри существующие записи как примеры.

`GuiLayouts.register(id, width, height, List<SlotPosition>)` регистрирует MenuType и раскладку. SlotPosition задаёт индекс серверного инвентаря, x/y и признак выхода. Клиент автоматически связывает все раскладки с `MachineScreen`; общий `MachineMenu` обрабатывает shift-click и синхронизацию 12 полей, включая энергию без потери старших битов. Дополнительные показатели и специализированное поведение расширяются в этих классах.

`ProcessingRecipes.recipe(kind, input, inputCount, output, outputCount)` добавляет рецепт дробителя/пресса до запуска мира. Категории JEI берут записи из того же реестра. Рецепты пока регистрируются Java-кодом, не datapack JSON.


## Своя 3D-модель настройщика

Новая модель не создавалась: по умолчанию сохранена прежняя текстура инструмента. Внутренний ID `smog:wrench` оставлен для совместимости с сохранёнными предметами; отображаемое имя — «Настройщик» / Configurator.

Чтобы подключить свою модель:

1. Экспортируй модель из Blockbench в формате Minecraft Java Block/Item JSON в `src/main/resources/assets/smog/models/item/configurator.json`.
2. Положи её PNG в `src/main/resources/assets/smog/textures/item/`, в JSON используй ссылку `smog:item/<имя>`.
3. В записи предмета `wrench` каталога `src/main/content/smog.content.json` добавь поле `"model": "smog:item/configurator"`.
4. Пересобери мод. Геометрия и секция `display` твоего JSON определяют вид в GUI, в руках и на земле.

Поле `model` поддерживается всеми предметами массива `items`. Если оно отсутствует, остаётся стандартная модель из текстуры. Исходный JSON пользовательской модели не генерируется и не перезаписывается сборкой.


## Текстуры интерфейсов

Все собственные элементы GUI рисуются из редактируемых PNG в `src/main/resources/assets/smog/textures/gui/`:

| Файл | Размер | Назначение |
|---|---|---|
| `processor.png`, `generator.png`, `environment.png` | 176×190 | Фоны раскладок |
| `slot.png` | 18×18 | Фон одного слота |
| `button.png`, `button_hover.png`, `button_disabled.png` | 34×16 | Кнопка питания и её состояния |
| `voltage_button*.png` | 22×12 | Кнопка предела передачи |
| `progress_empty.png`, `progress_full.png` | 41×14 | Пустая/заполненная стрелка обработки |
| `energy_empty.png`, `energy_full.png` | 12×52 | Энергетический индикатор |
| `fuel_empty.png`, `fuel_full.png` | 14×14 | Остаток горения топлива |
| `structure_preview.png` | 162×76 | Фон превью JEI |

Надписи и числа использует стандартный шрифт Minecraft. Заливка прогресса обрезает заполненную PNG, не растягивая её. Геометрия слотов и их позиции задаются `GuiLayouts`; новый layout по умолчанию ищет `textures/gui/<id>.png`. Перегрузка `register(..., Identifier texture)` подключает другой фон. `TextureButton` обрабатывает собственные PNG обычного, наведённого и отключённого состояния.

`python tools/generate_gui_assets.py` создаёт только отсутствующие PNG и не заменяет ручные рисунки. Готовые PNG включены в репозиторий; для сборки Python не нужен. Сохраняй размеры файлов и используй пиксельную сетку без сглаживания.


Существующие коннекторы и старые провода сохраняют вертикальную ориентацию UP: новая ориентация крепления не переиспользует старое горизонтальное свойство facing. Направления обоих наконечников провода сохраняются в SavedData и передаются клиенту. Разные ориентации не позволяют создать вторую связь между той же парой коннекторов.
